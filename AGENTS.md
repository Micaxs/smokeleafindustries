# AGENTS.md

## Quick Start

```bash
./gradlew build              # Compile + package mod jar
./gradlew runClient          # Launch Minecraft client (dev)
./gradlew runServer          # Launch dedicated server
./gradlew runData            # Regenerate src/generated/resources/
./gradlew runGameTestServer  # Run game tests (only test mechanism)
```

CI runs `./gradlew build` on push/PR (`.github/workflows/build.yml`).

**No unit tests** — only in-world NeoForge game tests via `runGameTestServer`.

## Key Architecture

- **NeoForge 1.21.1** (NeoGradle / ModDevGradle), **Java 21**, mod_id `smokeleafindustries`, base pkg `net.micaxs.smokeleaf`
- Entry: `SmokeleafIndustries.java` (`@Mod("smokeleafindustries")`) — all `.register(modEventBus)` calls in constructor
- Client entry: `SmokeleafIndustriesClient.java` (screens, renderers, colors, particle factories). Every new fluid needs `ItemBlockRenderTypes.setRenderLayer(fluid, RenderType.translucent())` here.
- Datagen entry: `DataGenerators.java` — run `./gradlew runData` after adding blocks/items/models/recipes/loot

## Player Progression (machine order)

1. **Hemp** → harvest `hemp_leaf` (shear 4x) + `generic_bud` (break), craft hemp fibers/fabric/building mats
2. **Crop → Bud** → plant `generic_seeds` (+ `StrainData`) in crop block or Grow Pot → harvest `generic_bud` (+ `StrainData`)
3. **Drying** → Drying Rack (no power, 12 slots) or Dryer (electric, 2 slots) → sets `DRY=true` component on bud
4. **Grinding** → Manual Grinder (hand item) or Grinder (electric, 64000 FE) → `generic_bud` → `generic_weed` (strain data preserved, +1 bonus if dry)
5. **Consumables** → Crafting table: `weed` + paper + tobacco → Joint/Blunt (stored in NBT, not StrainData components)
6. **Power** → Generator (electric, burns weed/bud, 40 FE/t) — needed to run other machines
7. **Extraction** → Extractor (electric) → `generic_weed` → `generic_extract` (strain data preserved)
8. **Liquify** → Liquifier (electric, 8000mb tank) → `generic_extract` → fluid extract (strain data on FluidStack)
9. **Mixing** → Mixer (electric, dual 4000mb input tanks + 8000mb output) → two extract fluids (250mb each) → 500mb `UnidentifiedMixtureFluid` with combined StrainData
10. **Mutation** → Mutator (electric) → `generic_seeds` + extract item + mixture fluid → seeds with custom StrainData from mixture
11. **DNA** → Synthesizer (electric) → empty `DNA_STRAND` + 3 reagents → filled `DNA_STRAND`; Sequencer (electric) → filled DNA + base extract → output with strain (no Sequencer recipes exist yet)

## Strain System (Mid-Migration)

The mod is being rewritten from **25 per-strain items** to a **generic item + `StrainData` component** system.

### New system (preferred)
- 4 generic items: `GENERIC_SEEDS`, `GENERIC_BUD`, `GENERIC_WEED`, `GENERIC_EXTRACT`
- `StrainData` record (Codec-serialized, NeoForge data component `STRAIN_DATA`) on all items and FluidStacks
- 25 preset strains in `StrainRegistry`, overridable via datapack JSON
- `StrainUtil` helpers: `hasStrain()`, `getStrain()`, `setStrain()` — use these, never raw component access
- `StrainRegistry.reload()` called on server start from `ModStrainRegistry.STRAIN_REGISTRY_KEY`
- `StrainEffectsUtil` builds `MobEffectInstance` list from StrainData (CBD scales duration, THC determines extra effect count)
- `StrainItemFactory` creates items with full strain data via `applyPreset()`

### Old system (still partially present, being phased out)
- 25 separate per-strain **bags** and **gummies** still registered as individual items
- 25 separate named **extract fluids** still in `ModFluids`/`ModFluidTypes` (not consolidated to generic)
- `WeedDerivedItem` (cake, brownie, cookies) uses legacy `CustomData` NBT for effects, not `StrainData`
- `JointItem`/`BluntItem` store weed in their own NBT, not `StrainData`
- Individual `THC`, `CBD`, `NPK`, `ACTIVE_INGREDIENT`, `EFFECT_DURATION` data components still present as legacy fallback

### Dual paths on FluidStacks
- `WEED_FLUID_DATA` (old) — used for effect application via `WeedFluidStackUtil`
- `STRAIN_DATA` (new) — used for tinting, mixing, lineage tracking
- Both must be set on extract/mixture fluids (Liquifier BE handles this)

## Rules That Save Time

1. **MODID is `smokeleafindustries`** — use `SmokeleafIndustries.MODID` constant, never `smokeleaf`
2. **Do not edit `src/generated/resources/`** — it's regenerated by `runData`. Always run datagen after changes.
3. **Machine pattern**: `XxxBlock` (with `POWERED`) → `XxxBlockEntity` (tick, energy, inventory) → `XxxRecipe` + `XxxRecipeInput` → `XxxMenu` + `XxxScreen` → `XxxRecipeCategory` (JEI compat)
4. **Strain data flow**: recipes do NOT inherently propagate `StrainData` — each `assemble()` must copy it explicitly. Check both the recipe AND block entity for where strain is handled.
5. **BlockItem auto-registration**: `ModBlocks.registerBlock(name, supplier)` registers both block and its `BlockItem`
6. **Energy**: `ModEnergyStorage` wrapper, exposed via `IEnergyStorage` capability per side; Generator pushes FE to neighbors
7. **Prefer new system**: always use `StrainUtil.getStrain()`/`setStrain()` first, fall back to legacy `THC`/`CBD` individual components
8. **Strain stats are deterministic**: `StrainUtil.finalizeMixtureStats()` uses a deterministic seed from `strainId` — same ID always gets same stats
